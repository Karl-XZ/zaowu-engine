# 产品需求文档 PRD

**Aholo Lux3D × Text-to-CAD × 支付宝 Vibe Pay × 嘉立创 3D 打印**

版本：V1.4  
日期：2026 年 11 月 12 日

**业务规则**

每个账户每日免费成功生成 3 个 3D 模型；超出后 5 元/次。创意模型与精确 CAD 共用额度。已生成模型的旋转预览、查看历史与文件下载免费。实体制造与物流由嘉立创履约，平台收入仅来自模型生成服务。

面向礼物设计的双引擎 3D 生成服务。平台先判定输入是否适合制造与预算，再编译受约束的生成提示词和工具参数；通过高成功率、低调用次数的生成流程完成模型及制造验证，最后连接嘉立创打印。将平台 API 成本保护与用户合格交付保障同时设为硬性要求。

**阶段目标**

构建一套可线上访问、可真实生成模型并收取生成服务费的产品；优先支撑 Aholo、支付宝及创业赛事的真实操作演示。

# 01 产品概况与范围

## 1.1 产品定位

面向个人消费者、内容创作者及小型商家的 AI 3D 定制服务平台。用户先选定目标材料、尺寸和用途，再用一句话（或语音、参考图片）描述礼物。创意路线先由 AI 生成设计效果图，用户通过对话调整造型、风格和颜色（最多 10 次），确认后由 Aholo Lux3D 将效果图转换为三维模型；精确结构类需求由 CAD 引擎按参数生成。平台负责制造预检、必要的免费修复与版本预览，嘉立创负责正式生产审核、制造及物流。

## 1.2 产品目标

| 目标类别 | 具体目标 | 验收证据 |
|---|---|---|
| 功能闭环 | 需求输入 → 生成 → 三维预览 → 文件输出 → 生产报价/下单入口 | 真实用户可完整执行并留下任务记录 |
| 两类生成 | 创意外观、参数化精确结构均可生成 | 不同样例各完成至少 5 次端到端测试 |
| 收费闭环 | 每日 3 次免费；超额 5 元，支付后能生成 | 支付宝沙箱支付、回调与退款测试通过 |
| 服务可信 | 任务可追踪、生成失败不扣额度、可复用历史模型 | 异常及并发测试通过 |
| 生产对接 | 能提供生产要求检查和嘉立创报价/下单通路 | 获批 API 或用户可实际操作的人工跳转流程 |

# 02 用户流程与产品信息架构

## 2.1 主流程

1. 用户进入首页，注册或登录，选择「创意 3D」或「精确 CAD」。

2. 选择目标物料/工艺与尺寸，输入一句话、语音或参考图片；系统在请求生成前核查结构约束。不符合制造规范的要求需先调整。**创意路线**进入设计会话：AI 生成设计效果图，用户可通过对话调整造型、风格和颜色最多 10 次，并在任一版本上点击「确认此图，转成 3D」（详见 §2.4）。**CAD 路线**录入毫米尺寸与结构参数，不经过效果图。

3. 服务端先执行输入/材料约束预检，再预留免费额度或付费生成权益。请求在后台执行并显示状态；超出免费额度时需先完成支付宝付款，但预付款在交付合格模型前不视为已核销。

4. 创意路线由 Lux3D 将确认的效果图转为 3D，CAD 路线由 CAD 内核建模；服务端保存源文件，执行修复、几何/壁厚/尺寸/连接/纹理/格式检测，并完成切片检查（§4.9）。发现可修复缺陷时在内部自动修复或有限次免费重试，复检通过才产生正式交付版本。

5. 用户预览通过制造预检的模型并确认版本；只有通过验收的交付才扣除一次免费额度或核销 5 元。因平台模型缺陷造成的修复/重试不重复收费；用户主动改设计按 §5.5 计次规则处理。

6. 用户选择「获取打印报价」，使用已锁定的合格制造文件与所选材料/尺寸/数量查询嘉立创；供应商不接受时先阻断正式下单并触发免费修复或退款流程。

7. 嘉立创接收生产订单及收货资料并负责制造配送；平台显示可获取的状态信息。

## 2.3 关键界面交互

- 创意与 CAD 两个入口保持视觉层次一致；用户可以明确知道本次生成由哪种引擎完成。
- 生成按钮旁持续显示「今日剩余免费次数」，付费前明确展示费用和退款规则。
- 任务进入队列、生成中、处理文件、质量检查等阶段时分别显示状态；不得将排队假装为即时完成。
- 三维预览支持鼠标/触屏旋转、缩放、重置视角、线框/实体切换（后者为 P1）。
- 预览支持显示验证结果；未通过制造预检的模型不得标为“生成成功”或“可打印”，不提供正式生产文件下载/制造下单。须给出可理解的缺陷、修复进度及不扣费说明。

## 2.4 创意路线：效果图对话设计（V1.4 新增）

| 环节 | 规则 |
|---|---|
| 开启会话 | 先确认材料、尺寸与用途，并预留 1 次生成权益（免费额度或已付 5 元权益）；无可用权益时先进入支付页 |
| 首张效果图 | 服务端以 DesignSpec + Prompt Compiler 生成：单一主体、一体底座/挂孔、无悬空碎片、干净浅色背景、四分之三视角、完整无遮挡，便于后续图生 3D |
| 对话调整 | 每次调整为一次对话指令，可针对造型、风格、颜色；以上一版为参考图做编辑，保持主体一致；**每个会话最多 10 次**，界面持续显示「剩余 N/10 次」 |
| 版本 | 首图记为 v0，每次调整产生 v1…v10；所有版本保留，可对比、可回退，可在任一版本上确认 |
| 每次调整前的预检 | 本地规则先检查指令是否引入不可制造结构（悬空、细杆、分离部件、超尺寸等）；不合格先给建议，不调用付费接口，**不消耗调整次数** |
| 次数用完 | 不再接受调整；用户可从 v0～v10 中选择一张确认转 3D，或放弃本会话后新开会话（需重新预留权益） |
| 颜色说明 | 选择单色材料时，颜色调整只影响效果图，打印件为所选材料本色；界面须在颜色调整时提示 |
| 确认转 3D | 对确认的效果图做本地图像质检（单主体、背景、遮挡、清晰度），通过后经 Cost Governor 批准再调用 Lux3D；需要文字约束时按 §3.1 走文生 3D 的 img + prompt 接口 |
| 平台修正轮 | 3D 制造预检不通过且需改效果图才能修复时，平台发起的“可制造性修正”不计入 10 次，也不计费 |

# 03 生成引擎功能需求

## 3.1 创意生成：Aholo Lux3D

生成类型包括文生 3D、图生 3D、文字加参考图生成 3D。V1.4 起创意路线的默认主路径为：**用户确认的 AI 效果图 → Lux3D 图生 3D**。

服务端把用户需求转成结构化设计规格，自动选择接口、模型版本、style、尺寸及生成参数，并先评估材料制造风险与预期 API 成本。

注意：当前公开的纯图生 3D 接口未列出 prompt 字段；需要图片与结构约束同时生效时，优先使用支持 img + prompt 的文生 3D 接口，或先处理参考图再调用纯图生 3D。不能假定在纯图生接口里加入额外 prompt 会被支持。无论使用哪条路线，均需独立进行几何制造检测。[R15][R16]

| 需求 ID | 功能与业务规则 | 验收标准 |
|---|---|---|
| GEN-A01 | 选择文生 3D 或图生 3D；文字含风格、主体、材质、细节，图片需做格式和大小检查。 | 提交有效请求后返回平台任务 ID。 |
| GEN-A02 | 适配 G1/G1-Turbo；按真实账户扣费、平均交付成本、质量与失败率选择默认版本。Turbo 速度更快或输出更轻不自动代表更便宜。 | 可切换且保留版本、请求参数、实际扣费、成功率；未经成本验证不得扩大免费流量。 |
| GEN-A03 | 按 Aholo 官方任务状态轮询；避免前端长连接等待外部任务。 | 超时、取消、失败具备明确状态与恢复入口。 |
| GEN-A04 | 下载 GLB/PBR 或官方导出文件；立即转存至平台对象存储，保留来源信息。 | 即使官方短期 URL 过期，用户仍可打开历史模型。 |
| GEN-A05 | 设计效果图为创意路线的默认必经步骤（V1.4）。多视图仍为可选，仅在实测能明显提高图生 3D 合格率时启用；不得为每次调整自动调用多视图接口。 | 未经用户确认的效果图不得进入 3D 生成。 |
| GEN-A06 | 用户修改语言描述生成新版本，保留原版本与提示词（敏感信息脱敏）。 | 旧版本不会被覆盖，新版本成功后扣一次额度。 |
| GEN-A07 | 生成任务必须携带 targetMaterial、processProfile、targetSizeMm 与 printIntent；服务端以材料档案组装约束提示词，默认禁止悬浮薄件和无支撑细杆。 | 创建任务前检查材料配置存在且所有硬约束已确定。 |
| GEN-A08 | 输出后优先本地网格修复；仅在剩余任务成本预算允许时，重调用 Aholo。无法按预算产生合格模型则结束并返还权益，不扣除成功生成次数。 | 任一不合格模型不扣次、不支付核销、不开放打印下单。 |
| GEN-A09 | 提示词由服务端 Prompt Compiler 统一生成，分离用户需求、工艺硬约束、模型参数与风格，保存模板版本并做回归测试。 | 对相同结构需求输出稳定、合法的生成参数；不让用户提示覆盖制造规则。 |
| GEN-A10 | 纯图生 3D 没有文档化 prompt 字段。对需要制造提示词的参考图需求，使用文生 3D 的 img + prompt 或先编辑参考图后图生 3D。 | 不得向未文档化接口字段发送约束提示词并假定其生效。 |
| GEN-A11 | 单色模型评估 G1-Turbo 的 enablePbr=false、GLB 单格式和合适 faceCount；所有节约须通过真实调用成本及可制造率验证。 | 保存结果大小/贴图/实际扣费，单色不因缺少 PBR 而影响打印文件结构。 |

## 3.2 精确生成：Text-to-CAD

面向尺寸、机械连接、孔位、对称、倒角等明确几何约束。

用户输入自然语言与参数，系统在生成参数化脚本前注入材料最小尺寸、厚度与间隙规则，并由真实 CAD 内核执行、校验及导出。所有长度单位统一为毫米（mm）；违反硬性约束的建模结果必须判为失败并自动更正。

| 需求 ID | 功能与业务规则 | 验收标准 |
|---|---|---|
| GEN-C01 | 语义解析：抽取类型、尺寸、孔径、位置、厚度、数量、连接关系；缺失关键尺寸时提示补充。 | 可结构化展示参数，用户确认后执行。 |
| GEN-C02 | 优先使用零模型费的参数化模板和本地 build123d/CadQuery；不能表达时才让低成本 LLM 生成受限脚本，在隔离环境执行。 | 可对标准结构输出 STEP 与 STL。 |
| GEN-C03 | 对代码实行白名单、静态扫描、资源限制、无网络执行与超时终止。 | 恶意脚本无法访问宿主或私有密钥。 |
| GEN-C04 | 真实几何计算后检查实体数量、尺寸、边界盒、非零体积、孔位等约束。 | 尺寸和结构不合格时不给“生成成功”状态。 |
| GEN-C05 | 支持参数表调整并重新构建；纯参数重建可设计为免费本地操作，涉及新的 LLM 生成才计次。 | 同脚本变更尺寸可完成自动重算和版本管理。 |
| GEN-C06 | 工程输出 STEP 优先，供打印的 STL/3MF 和网页 GLB 由平台转换生成。 | 三种文件能相互关联到同一模型版本。 |
| GEN-C07 | CAD 脚本在构建之前绑定材料最小壁厚、孔径、装配间隙、零件连通等硬约束；构建后进行实测验证。 | 违反设计约束时自动重建或失败退还权益。 |
| GEN-C08 | 对铭牌/挂件/底座/简单外壳/尺寸化浮雕先匹配预设可验证参数模板，避免每次调用大模型写完整 CAD 程序。 | 模板命中的任务仅发生本地建模与可控运行成本，输出 STEP/STL/GLB。 |
| GEN-C09 | CAD LLM 失败优先本地编译错误修复、参数补全或安全重建；再次请求 LLM 受成本预算限制。 | 脚本重复执行不额外收费，供应商模型调用次数受任务预算约束。 |

**CAD 引擎交付边界**

首版优先覆盖钥匙扣、铭牌、底座、收纳盒、简单外壳、指定孔位和几何结构。不承诺任意雕塑、复杂人物或高精度装配件自动成功。精确尺寸必须在 CAD 内核中校验。

## 3.3 双引擎路由策略

| 输入特征 | 默认路由 | 可覆盖条件 |
|---|---|---|
| 强调人物、宠物、卡通、造型与外观 | Aholo Lux3D | 用户手动选择 CAD，或同时指定严格尺寸 |
| 存在具体孔径、公差、装配、厚度等工程约束 | Text-to-CAD | 用户明确要求创意外观时可先生成视觉模型 |
| 既需要造型又需要可量化结构 | 先 Aholo 外观 + CAD 子结构；首版不自动拼装 | P2 支持两路线融合与配准 |

## 3.4 生成前的可行性与成本双预检

在任意收费的 3D 模型或图片 API 调用前，必须完成本地校验。

先依据材料档案和产品品类建立设计限制，再判定此次请求是「可用本地 CAD 模板」「可直接进入 Aholo」「需要用户确认简化方案」「当前不支持」。

同时估计调用次数、潜在 API 成本和通过率；预算不足的任务在调用前阻断。

| 风险信号 | 调用前处理 | 外部付费调用 |
|---|---|---|
| 多个主体互不连接、悬空细杆、极薄花边 | 先建议合并主体、增厚细节、增设底座；用户确认后生成 | 用户拒绝必要调整 → 不调用 |
| 精确孔径、卡扣、装配间隙及固定尺寸 | 转 CAD 参数化模板；校验材料公差与尺寸 | 通常不走创意 Aholo |
| 参考图模糊、遮挡、多主体或水印明显 | 客户端/服务端本地图像质量检查，要求裁切或替换图片 | 图像不合格 → 不调用 |
| 过细文字、微型复杂纹理、不支持的几何 | 由材料档案给出最小特征要求；建议简化或调整尺寸 | 无法满足 → 不调用 |
| 超出成本上限或预估成功率过低 | 优先切换本地模板/低成本引擎；展示不支持的理由 | 不得先付费试错 |

## 3.5 Prompt Compiler：后台统一构建模型生成指令

禁止把未经处理的用户原始文本直接作为唯一供应商提示词。

后台先创建版本化 DesignSpec（产品类型、单体/分体、目标尺寸 mm、目标材料与工艺、风格、重要外观元素、文字内容、部件关系、限制与风险、参考图信息），执行 JSON Schema 结构验证和制造规则校验。只有验收通过的规格才能编译为 API 请求。

- **模板选型：** 钥匙扣、桌面摆件、卡通宠物、铭牌、徽章、手机支架、盒体等采用独立的工艺提示词模板；针对材料与尺寸绑定参数，防止泛化提示词导致批量缺陷。
- **文生 3D：** 将“主体、主要造型、稳定底座/悬挂结构、一体连接、可读细节、目标尺寸、风格、要避免的脆弱结构”等要素编译进 prompt；style 使用文档允许的枚举值。
- **参考图：** 优先提取单体、清晰轮廓、三分之四视角、无遮挡及干净背景。纯图生 3D 若需提示词约束，改走支持参考图的文生 3D API；不得依赖没有公开支持的 prompt 参数。
- **精确 CAD：** 几何硬约束由结构化参数和建模内核落实；LLM 只产生允许的建模动作或参数，不能覆盖厚度、尺寸、闭合或连接规则。
- **生成参数：** 固定尺寸优先传 customSize（毫米）；针对单色模型试验 enablePbr=false；faceCount 只控制目标网格面数，不以它替代制造标准。参数的质量与成本收益需 A/B 实测。
- **用户修改：** 尽可能复用已有模型、原始规格与公共模板，仅编译修改差异；适用于 CAD 的改动直接本地重建，避免每次修改都重新调用 Aholo。

## 3.6 供应商调用前的成本调度器（Cost Governor）

所有可能扣费的步骤必须先由 Cost Governor 批准。

预算以人民币记账，单次任务允许的总支出 = 预设 API 成本预算；生成调用、图片处理、多视图、材质生成、重新生成、云端 CAD LLM 等共同占用预算。

成本未知时不得视为 0 元。

| 控制项 | 执行要求 | 失败/超限处理 |
|---|---|---|
| 调用前预算预留 | 根据真实供应商计费表与任务路线预计费用，原子预留 budget_reserved | 预算不足时停止，先释放权益/说明无法完成 |
| 限额与熔断 | 按用户、引擎、免费/付费类型、日预算设置阈值；超限不开新任务 | 控制新增调用，不影响已生成模型下载 |
| 付费重试 | 优先本地几何修复；重新生成仅当剩余预算覆盖新调用及预计收尾成本 | 不够则失败并退回对应生成权益 |
| 幂等与超时 | 对一次供应商 taskid 持续查询；网络超时先查状态和扣费 | 确认未创建任务才允许再次创建 |
| 账单核对 | 记录预计成本、实际供应商扣费、返回码、任务/模板/模型版本及修复成本 | 每日与供应商控制台或账单对账 |
| 异常成本 | 出现连续 API 失败、成本暴增、收费口径变化时触发全局熔断 | 暂停该引擎、保留其他可运行路线 |

## 3.7 默认路由与试运营准入

- 默认路由 ①：尺寸清楚的牌、座、壳、扣、几何文字礼物 → 优先预置 CAD 模板；用户调尺寸只重算参数，几乎不产生模型 API 费用。
- 默认路由 ②：单主体卡通/装饰类礼物 → 本地请求审核、设计规格编译 → 效果图对话设计（≤10 次）→ 确认后进入已测过成本和合格率的 Lux3D 图生 3D 版本。
- 默认路由 ③：参考图 + 打印约束 → 首选文生 3D 的参考图联合输入；纯图生 3D 用于无需文字约束或经过前处理的低风险图片。
- 默认路由 ④：复杂机械结构、精密配合、极细人物发丝等首版禁区 → 提示不支持或引导至可实现版本，禁止以重复生成碰运气。
- 每一类别须先完成小样本验证：记录首轮制造预检合格率、嘉立创接收率、单位合格交付成本、用户改稿率。未达到内部门槛的类别，不进入公共免费池。
- 免费每日 3 次与付费 5 元是对外规则；三次免费完整 3D 生成会产生真实成本。如果不能在预算内履行该承诺，必须在上线前调整免费可用模型/类别或活动规则并如实告知，不能以失败任务、伪预览或隐性限额冒充三次成功生成。

# 04 3D 预览、文件与可制造性

## 4.1 网页预览

- 使用 Three.js 或 model-viewer 预览 GLB/GLTF；适配桌面浏览器与移动端触控。
- 显示方向坐标、尺寸（mm）、近似体积、颜色/纹理、模型版本和处理状态。
- 对大文件生成预览优化副本；保留用于生产的原始高质量文件。
- 支持用户确认版本并锁定生产文件；确认后的文件不可被后续生成静默替换。

## 4.2 文件标准与导出

| 用途 | 建议格式 | 说明 |
|---|---|---|
| 网页浏览 | GLB/GLTF | 渲染格式；可保留纹理，但不等同于打印文件。 |
| 单色 3D 打印 | STL | 仅网格几何，无颜色信息，单位需由平台写入元数据和下单表单。 |
| 工程结构与尺寸 | STEP/STP | 参数化 CAD 模型的交付主格式。 |
| 彩色生产 | OBJ + MTL + PNG ZIP，或供应商确认的 3MF | 模型与纹理一致；按嘉立创现行文件要求打包。 |

所有壁厚、孔径和连接规范由选定的嘉立创材料/工艺档案决定，禁止统一用某个数值覆盖全部工艺。

嘉立创公开设计规范推荐模型壁厚 2 mm，并对全彩树脂文创易损或悬空结构推荐 2 mm 以上；具体规则应随材料、用途更新。[R4][R13][R14]

## 4.3 生成后制造预检（强制验收）

| 检查项 | 处理规则 | 结果等级 |
|---|---|---|
| 几何有效 | 有效实体、封闭性/水密性、流形性、自交、法线方向、孤立几何及非零体积。 | 硬性不合格 → 阻断 |
| 尺寸与体积 | 统一 mm 单位、外形尺寸与材料设备限制；尺寸超标自动建议等比缩小，需用户确认。 | 超出范围 → 阻断 |
| 最小壁厚与连接 | 按目标材料档案检查最小壁厚、细杆、悬空结构、连通面积和必要支撑；不可测时不允许自动判为通过。 | 不确定 → 人工复核/阻断 |
| 纹理一致性 | 彩色文件的 UV、材质、贴图完整；网格修复后复查纹理、外观及结构一致性。 | 贴图损坏 → 修复/阻断 |
| 供应商文件规范 | 格式、文件大小、压缩包组织及用户目标工艺；合格文件才允许创建制造报价/下单任务。 | 硬性不合格 → 阻断 |

平台制造检查为收费交付的强制门槛：未通过不得消耗生成次数或核销费用。

平台预检通过仅表示符合所选材料的当前自动规则，仍需嘉立创的实际审核；因平台文件缺陷被嘉立创拒收时，提供免费修复或重生，仍失败则恢复免费次数或原路退还该次生成费。

**壁厚与细杆检测的实现方案（V1.3 新增）**

Trimesh 只提供边界盒、体积、水密性等基础检查，没有现成的壁厚分析，须由平台自行实现：

- **先修复后测量：** 用 manifold3d / PyMeshFix 等工具做闭合、去自交、合并重复顶点，得到水密流形网格后才进入壁厚测量；修复本身须通过 §4.5 的外形与纹理一致性复检。
- **壁厚（射线法）：** 在表面均匀采样（采样数随面积版本化配置），沿反法线方向发射射线求对侧表面距离；以最小值和 P5 分位与材料档案的最小壁厚比较，并记录不合格区域供预览高亮。
- **细杆与薄片（体素/SDF 法）：** 将模型体素化或计算有符号距离场，以中轴近似截面半径，识别低于材料最小特征尺寸的细杆、尖耳、薄花边。
- **CAD 路线：** 壁厚、孔径、间距由参数与 B-rep 实体直接校验（OpenCASCADE 距离查询），不依赖网格射线。
- **不可测即阻断：** 修复后仍非水密、采样覆盖不足或检测超时，判为“不可测”，按上表转人工复核或阻断，不得默认通过。
- **版本化：** 采样密度、分位阈值、体素分辨率随 materialProfileVersion 一起版本化，写入 manufacturing_checks。
- **M0 可行性门槛：** 用不少于 20 个真实 Aholo 输出测量修复后水密率、可测率、壁厚合格率与单次检测耗时。若可测率低于 80%【待确认】，须先调整引擎参数（faceCount、模板）或缩小 Aholo 开放类别，再进入 M1。

## 4.4 制造约束必须参与生成

在点击“开始生成”之前，服务端必须创建制造目标档案（材料、工艺、尺寸范围、用途、色彩需求、最小壁厚与间隙），并将其绑定当前生成请求。

MVP 推荐从少量常用的嘉立创材料档案开始逐个验证，不支持用户随意选择全部材料。

- **生成前：** 分析用户要求中的薄壁、悬空构件、过长细杆、复杂镂空、尺寸矛盾等不可制造风险；可自动修改的先给出可解释的建议，需用户改变核心外观时先确认，再执行有成本的模型 API。
- **创意 Aholo：** 把材料约束注入生成任务，同时尽量选择可自支撑的一体化造型、稳固底座和简单连接结构。提示词只能降低风险，不能充当已通过验证的证据。
- **精确 CAD：** 以材料标准约束几何参数和建模脚本，生成前校验尺寸/间隙逻辑，生成后由几何内核检查体积、连通和实体尺寸。
- 不同材料、不同尺寸或纹理导出方式应分别产生验证结论；用户改变材料/尺寸后，原制造验收结果立即失效。

## 4.5 自动修复与交付门槛

- 生成输出后先检查网格、非流形边、法线、孔洞、连通区域、实际壁厚、支撑风险、毫米尺寸与生产文件格式。发现不合格，使用网格修复或 CAD 重新建模，并复检修复结果；修复不得无提示地改变主要外形或破坏纹理。
- 平台优先采用本地几何修复、尺寸调整或参数化重建。付费 API 重生成默认不自动开启；只有预计新增成本仍低于该任务剩余预算、且重生成明确有较高成功概率时，才允许再调用一次。重试次数是辅助限制，实际以累计人民币成本上限和供应商计费状态为硬门槛。不得为了追求必交付而无限次调用第三方 API。
- 只有满足“可预览 + 可下载 + 按已选材料通过自动制造预检”三个条件，才标记 VERIFIED_DELIVERABLE，核销免费额度或 5 元权益。任何警告不确定且可能导致制造失败的状态，都不得自动视为通过。
- 即便平台预检通过，仍可能因供应商工艺要求或人工审核被拒收。应保存检验报告、规则版本与生产文件哈希供追溯；因平台模型缺陷拒收时启动免费修复，无法修复则恢复免费次数或退还本次模型生成费；该责任的适用期限与条件见 §4.8。

## 4.6 收费与供应商责任边界

平台向用户提供的 5 元服务交付标准，是针对生成时约定材料与尺寸的“经平台制造预检合格的可交付模型”。

本地自动检查不能等同于嘉立创正式接单保证。

若平台的模型设计/导出缺陷导致厂商拒收，应承担免费修复与本次生成费退款；制造费、加工质量与物流退款按用户与嘉立创交易合同办理，平台协助提供证据，不得承诺代替嘉立创退回其直接收取的费用。

## 4.7 平台与供应商双重验证结果的经济责任

生成后的制造验证继续保留，但不再作为主要降本措施。

流程优先级为：

**请求前阻断无效需求 → 编译制造友好提示词/选择模型 → 预算审核后付费调用 → 本地修复与独立验收 → 嘉立创报价/审核。**

若用户未获合格成果则退还权益；平台将该次真实 API 支出记为失败损失，进入次日策略修订，不能简单视为“无成本失败”。

## 4.8 供应商拒收的平台责任期限（V1.3 新增）

平台对“因平台文件缺陷被嘉立创拒收”承担免费修复与退款责任，须**同时满足**以下条件：

| 条件 | 规则 |
|---|---|
| 时间窗口 | 自模型版本进入 VERIFIED_DELIVERABLE 起 30 天内【待确认】提交嘉立创并被拒收，以嘉立创审核记录时间为准 |
| 文件一致 | 提交文件的 SHA-256 与平台锁定的生产文件一致；用户自行修改、重新导出或缩放过的文件不在范围内 |
| 参数一致 | 材料、工艺、尺寸与平台验收时的制造目标档案一致 |
| 原因归属 | 拒收原因属于几何/结构/文件规范类（壁厚、细杆、悬空、非流形、格式、纹理包结构等）；产能、缺料、价格、物流、收件资料等原因不属平台责任 |
| 规范变更 | 窗口内嘉立创更新审核规范导致拒收，仍按平台责任处理；平台须在得知规范更新后 7 天内【待确认】更新材料档案并使旧验收结果失效 |

**处理：** 先免费修复或重生成（受单任务预算上限）；仍无法交付时恢复权益或原路退款（见 §5.3）。

**超出窗口或条件不满足：** 平台不再承担退款责任，可按 §5.5 计次规则提供“重新适配当前规范”，并协助用户提供证据。

## 4.9 切片检查（V1.4 新增）

- **目的：** 在交付前用真实切片验证可打印性，而不只做几何检测；嘉立创仍会按其工艺自行切片生产，平台切片结果不替代厂商审核。
- **实现：** 预检通过后，用 OrcaSlicer / PrusaSlicer 命令行按所选材料档案切片，记录支撑体积、悬垂孤岛、首层接触面积、层数、预计打印时间与耗材量。
- **判定：** 切片失败、出现无法支撑的孤岛、首层接触面积低于材料档案阈值，视同制造预检不通过，进入 §4.5 的修复流程，不计次。
- **输出：** 带切片报告的 3MF 进入生产文件包；G-code 默认不提供（家用打印机导出为 P2）。切片参数随 materialProfileVersion 版本化。

## 5.2 支付宝 Vibe Pay / AI 付

优先采用 Vibe Pay 基础收款能力，自己维护订单、生成权益和余额账本。

官方“智能收款套件”当前主要经合作平台提供，独立接入限制应按开通状态核实。为 PAYATHON 参赛保留支付链路日志与真实交付证据。[R3]

1. 用户今日可用免费额度为 0，确认下一次生成时展示「5 元/次」，生成请求进入待支付状态。
2. 服务端创建唯一支付订单，提供支付宝支付页面/扫码或相应客户端流程。
3. 收到支付宝异步回调后在服务端验签，再主动查询支付状态；确认成功后发放一次付费生成权益。
4. 任务开始时冻结该次权益，成功完成后核销；系统/供应商失败则释放或按支付规则自动退款。
5. 同一支付回调和同一生成请求都只执行一次权益入账/扣减，任何重试不得重复收费。

**支付冻结与权益恢复（V1.3 新增）**

- **优先方案：** M0 阶段核实 Vibe Pay 是否支持预授权/资金冻结或“先授权后扣款”类能力。若支持，采用“冻结 5 元 → VERIFIED_DELIVERABLE 后完成扣款 → 失败解冻”，失败任务不产生退款交易。
- **备选方案：** 不支持冻结时沿用“先付款后核销”。付费任务失败后默认把该笔恢复为账户内的“付费生成权益”，可直接用于下一次生成；用户可随时对未使用的权益申请原路退款，未使用权益 30 天【待确认】后自动原路退款。
- **合规边界：** 权益只能由单笔 5 元订单产生，不提供充值、不可提现、不可转让；单账户未使用权益上限 3 次【待确认】。上线前须由法务确认不构成预付卡/储值业务。

## 5.4 免费额度与单任务成本边界

- 免费任务与付费任务都需要预设成本上限和引擎准入规则。每个账户的三次免费成功生成与平台每日免费调用总预算分开记账；内部 API 花费不能用“退还免费次数”冲销。
- 对同一请求重复点击生成时使用客户端请求唯一 ID，服务端查询既有 taskid，不重复扣次也不重复创建付费生成。已在运行的任务不得通过刷新页面规避预算。
- 用户付费 5 元是针对一件合格模型的服务价格。若选择的模型类别需要超过 5 元的最低 API 成本，默认拒绝该路线或使用更低成本方案；不能为了履行 5 元价格而启动必然亏损的高费调用。
- 免费额度是否开放某个 Aholo 版本取决于该版本的真实单位合格交付成本和获客转化测算；每日日预算耗尽时须清楚展示免费服务当前不可用，并给出下次可用时间或等价替代，不承诺无限量提供。
- 后台以“供应商实际人民币扣费”为准计算毛利：模型调用、重试、图片、多视图、LLM、存储、支付费用都要进入成本；因失败退款给用户的任务也保留支出记录。
- 由于失败任务不扣成功次数，“免费 3 次”本身不能限制平台成本；必须同时执行 §5.1 的失败尝试与失败成本上限，否则用户可反复提交易失败需求消耗外部 API 费用。

## 5.6 “主要需求未实现”判定与申诉（V1.3 新增）

- **判定依据：** 生成前从 DesignSpec 提取“硬性要素清单”，包括主体类别与数量、指定文字内容、指定结构要素（底座、挂孔、孔位等）、指定尺寸及容差、单色/彩色。清单在生成（及付款）前展示，由用户确认。创意路线另以用户确认的效果图作为外观参照：3D 模型与确认效果图的主体、数量、主要造型结构明显不符，属平台责任；材质质感、细节锐度等图生 3D 的正常差异不属此类。
- **属平台责任：** 清单中的要素缺失、错误或数量不符；指定文字不可读；CAD 尺寸超出容差（通常已在交付前被几何内核拦截）。处理为免费重生成 1 次（受单任务预算），仍不满足则恢复权益或退款，且不计次。
- **不属平台责任：** 风格、表情、比例、细节美感、颜色偏好等未列入清单的主观评价。可再次生成，按 §5.5 计次。
- **申诉窗口：** 交付后 24 小时内【待确认】，且尚未下载正式生产文件、尚未提交嘉立创。网页预览与 GLB 查看不影响申诉资格。
- **流程：** 用户勾选未实现的清单项 → 系统自动比对（CAD 尺寸、文字等可自动校验项）→ 无法自动判定的转人工，48 小时内【待确认】答复。
- **公开展示：** 本规则须在首页价格说明、支付页和生成按钮旁可见，与 §2.3 一致。

# 06 嘉立创制造与一键下单

## 6.1 业务目标

平台不自建生产线，嘉立创承担其合同约定的材料、生产审核、打印、质检、物流和制造售后。

用户的制造费用原则上直接向嘉立创支付，平台只收模型生成服务费。

下单前展示供应商实际报价，不承诺制造成本固定在 30–50 元。

## 6.2 接入能力与边界

嘉立创已公开开放 3D 打印材料查询、报价、下单、进度与物流查询等 API；接口免费，3D 打印权限需要人工审核。

公开资料尚未证明支持“由个人用户直接向嘉立创付款、平台代创建订单并把货寄给不同收件人”的完整授权流程，应由嘉立创商务确认。[R5][R6]

| 能力 | 模式 A：API 审核通过 | 模式 B：API 暂未开通 |
|---|---|---|
| 报价 | 后台发送生产文件、材料、尺寸及数量并获取真实报价 | 提供推荐材料和文件，用户前往嘉立创官网查询 |
| 下单 | 经用户确认后按接口权限创建/关联嘉立创订单 | 下载标准制造文件并跳转嘉立创上传页面 |
| 制造付款 | 优先尝试用户直接向嘉立创支付；是否支持需确认 | 用户在嘉立创完成付款 |
| 物流状态 | 供应商接口可用时显示订单和物流进度 | 由用户在嘉立创账户查询，平台可保存外部订单号 |
| 可用性说明 | 仅在真实联调通过后显示“一键下单” | 明确显示“导出并前往嘉立创下单” |

## 6.3 正式下单前的确认信息

- 模型版本及缩略图、文件类型、尺寸（mm）、材料、颜色工艺、数量。
- 制造商实际报价、预估生产时间和配送费用；来自嘉立创的数据原样展示并标注更新时间。
- 收件人、联系方式、收货地址的单独授权；只向嘉立创传输生产所需信息。
- 用户确认预检报告、目标材料/工艺、外观及知识产权；下单时锁定同一生产文件的 SHA-256。不得勾选“跳过厂家风险沟通/自行承担结构设计风险”的默认选项，除非用户被单独充分告知并明确确认。

## 8.4 对第三方接口的正确处理

- **Aholo：** 先按场景选择文生 3D 或图生 3D 的合法接口，并写入材料/尺寸与 Cost Governor 的预算准入；再提交异步任务。当前官方纯图生接口没有公开 prompt 字段，参考图附加制造约束可用支持 img + prompt 的文生 3D；G1-Turbo 单色可测试 enablePbr=false。中国区与全球区 Key/网关分开。外部任务成功不等于模型合格。[R15][R16]
- **支付：** 以支付宝异步回调和主动查单交叉确认，区分“已下单、待支付、支付成功、权益入账、权益核销、退款”。
- **嘉立创：** 正式接口以获批账号的开发指南确定；HTTP 200 之外还校验业务结果、报价及工艺审核。模型在提交前锁定版本，若材料/尺寸变化必须重新验证；不得默认跳过风险沟通。[R6][R13]
- **模型文件：** 原始 GLB、打印文件和预览压缩文件分别保存，并绑定同一个 modelVersionId 与 SHA-256 校验值。

## 9.2 状态模型

**生成任务状态：**

CREATED → INPUT_PREFLIGHT → QUOTA_RESERVED / PAYMENT_REQUIRED → QUEUED → RUNNING → PROCESSING_ASSET → MANUFACTURING_VALIDATION → SLICE_CHECK → VERIFIED_DELIVERABLE。

**设计会话（创意路线，V1.4）：**

OPENED（权益已预留）→ CONCEPT_READY ⇄ ADJUSTING（turnsUsed ≤ 10）→ CONFIRMED → 创建上方生成任务；另有 ABANDONED / EXPIRED（释放权益，成本入账）。

检测不合格进入 REPAIRING → MANUFACTURING_VALIDATION（限定次数）；仍失败进入 FAILED_REFUND / FREE_QUOTA_RELEASED。

供应商因平台文件拒收时，转入 SUPPLIER_REJECTED → REPAIRING / REFUND。

只有 VERIFIED_DELIVERABLE 才核销生成额度；供应商可接收性由正式生产审核进一步确认。

**支付订单：**

CREATED → WAITING_PAY → PAID → ENTITLEMENT_GRANTED → USED；

另有 CLOSED / REFUND_PENDING / REFUNDED。

所有外部状态变化记录来源和签名校验结果。

**制造订单：**

DRAFT → QUOTED → USER_CONFIRMED → SUPPLIER_SUBMITTED → SUPPLIER_APPROVED → IN_PRODUCTION → SHIPPED → DELIVERED；

另有 REJECTED / CANCELED / AFTER_SALES，采用嘉立创实际状态映射。

# 10 安全、隐私与合规

| 控制点 | 最低要求 |
|---|---|
| 上传照片和语音 | 显示用途与授权；默认私有；禁止无授权公开展示真人/宠物照片或纪念内容。 |
| 生成模型权利 | 确认用户对参考素材有使用权；说明第三方生成 API 的商用与作品归属按合同执行。 |
| 个人信息共享 | 收货信息只在用户确认生产订单时向嘉立创提供；避免用于广告或训练。 |
| 第三方数据处理 | 逐项核实 Aholo 国内区隐私政策、数据留存、模型训练用途、跨境传输与商用授权。 |
| 代码生成安全 | CAD 脚本在无网络隔离进程内运行；限制文件访问、内存、CPU、执行时间和依赖。 |
| 文件安全 | 对象存储私有桶；限时 URL；访问日志；删除账号时提供删除请求与保留期。 |
| 支付安全 | 金额以服务器计算；异步通知验签；订单查询复核；幂等和防重放；日志不记录密钥。 |
| 内容风控 | 拒绝违法和危险物品设计、侵权商标人物素材等；涉嫌侵权作品转人工审核。 |
| 供应商责任 | 制造质量、退改及生产可行性以嘉立创实际订单条款为准，用户下单前须知情。 |

# 12 运营指标与单位经济模型

## 12.1 事件与指标

- 曝光 → 注册 → 首次生成 → 制造预检合格 → 成功预览 → 二次生成 → 付费 → 下载 → 嘉立创报价 → 厂商审核通过 → 外部下单的各环节转化率。
- 分别统计首次生成制造预检通过率、内部自动修复成功率、重试 API 成本、最终合格交付率、嘉立创拒收率以及 P50/P95 等待时间。
- 每个合格交付模型的真实成本 = 原始生成调用 + 缺陷修复及失败重试 + 质检计算 + 其他模型服务 + 服务器成本；另统计免费用户成本、付费率与退款率。
- 按材料/类别统计嘉立创审核通过率、制造报价与用户预期差距；因平台模型缺陷拒收的占比应作为重要质量指标。

## 12.2 收费压力测试

| 单次成功生成全成本（假设） | 某用户当天 3 次免费 + 1 次付费的合计成本 | 该用户当日付费 | 可用余额（未扣固定成本） |
|---|---|---|---|
| ¥0.50 | ¥2.00 | ¥5.00 | ¥3.00 |
| ¥1.00 | ¥4.00 | ¥5.00 | ¥1.00 |
| ¥2.00 | ¥8.00 | ¥5.00 | −¥3.00 |
| ¥3.50 | ¥14.00 | ¥5.00 | −¥9.00 |

以上用于测试单价耐受性，不代表 Aholo 实际报价。

若用户只使用免费额度而不付费，平台承担其全部生成成本。

实际经营模型必须纳入新用户获客成本、支付手续费、失败重试、固定服务器费用、税费和售后。

## 12.3 试运营门槛

| 指标 | 建议上线前确认方式 |
|---|---|
| 单次模型真实成本 | 分别跑 G1、G1-Turbo、CAD 典型样例，记录供应商实际扣费和失败损失 |
| 可打印率 | 至少分别按创意模型、CAD、目标材料执行各 20 个样本，记录初次过检、修复、合格交付及实际嘉立创审核/报价结果 |
| 实际付费成功率 | 支付链路须包含“未通过制造预检自动恢复权益/原路退款”和“厂家拒收后的追溯退款”测试 |
| 真实用户反馈 | 邀请用户独立完成生成、预览、下载/下单，统计卡点与满意度 |
| 嘉立创订单接入 | 获取 API 审核结果与付款责任边界的书面确认 |

## 12.4 免费三次与五元定价的保本模型

平台需要计算“每个合格交付模型的真实全成本”：将所有成功任务、失败任务、重试、辅助生图、LLM、网格修复与后端费用相加，再除以真正交付的合格模型数量。

不能用单次生成 API 的标称价格替代这一指标。

简化保本关系：

**付费生成数 ×（5 元 − 付费模型平均全成本）≥ 免费生成数 × 免费模型平均全成本 + 固定/获客等费用。**

下表暂忽略固定费用、支付手续费和失败额外损失，按“100 个用户每天各领取 3 个免费模型（共 300 件）”作示例，所得结果是盈利的最低需求而非预测。

| 合格模型平均成本（假设） | 300 次免费总成本 | 每次付费模型剩余空间 | 需付费生成次数（至少） |
|---|---|---|---|
| ¥0.30 | ¥90.00 | ¥4.70 | 20 |
| ¥0.50 | ¥150.00 | ¥4.50 | 34 |
| ¥1.00 | ¥300.00 | ¥4.00 | 75 |
| ¥2.00 | ¥600.00 | ¥3.00 | 200 |
| ¥3.00 | ¥900.00 | ¥2.00 | 450 |

例如平均全成本为 2 元，单日 300 次免费生成产生 600 元成本，而每次 5 元付费生成只留下 3 元，需要至少 200 次额外付费生成才能单纯覆盖免费损耗。这还未计算经营固定费用。

实际免费领取率、付费转化和供应商失败扣费必须用真实试运营数据替换。

试运营阶段可先设内部目标值（非 Aholo 报价）：

- 免费档每件合格模型全成本尽量控制在 0.5 元以内。
- 付费档尽量控制在 1.5 元以内。

达不到时必须调整模型路线、补贴范围或收费方式，而不能靠增加失败重试掩盖亏损。

# 附录 A 开发验收的最小真实演示

1. 在未登录浏览器访问首页，登录后显示“今日免费剩余 3 次”。

2. 进入创意路线，选定单色树脂与 60 mm 小摆件规格，输入“一个站在月亮上的 Q 版小熊”，生成首张效果图；对话调整 2～3 次（如“耳朵再圆一点”“换成水彩风格”），展示剩余次数；确认后由 Lux3D 转为 3D，展示修复、壁厚预检、切片报告、合格生产文件及旋转预览。

3. 返回精确 CAD，输入“80 mm 长、30 mm 宽、4 mm 厚，两个直径 5 mm 对称孔的铭牌”，生成 STEP/STL 并核查尺寸。

4. 完成第三个通过制造预检的合格模型后，剩余免费额度为 0；生成中失败或未通过制造预检的任务不占成功次数。

5. 第四次点击生成显示 5 元付款，完成支付后冻结生成权益，平台制造预检通过才正式核销；故意生成异常模型并验证失败退款。

6. 展示同一模型在目标材料下的制造检查：预检合格后才提供嘉立创报价或生产文件；故意破损模型自动阻断、免费修复及复检。

7. 展示生成历史、材料约束版本、制造预检报告、供应商审核记录，以及系统生成缺陷造成嘉立创拒收后的免费修复或退款证据。

# 附录 C Prompt Compiler 与成本控制示例

## C.1 示例：用户输入与结构化 DesignSpec

用户原话：

“我要一个 6 厘米的 Q 版小熊摆件，脚要连着星形底座，耳朵不要太细，准备做单色树脂打印。”

结构化结果：

- category=figurine
- subject=cartoon bear
- sizeHeightMm=60
- materialProfile=validated_monochrome_resin_v1
- connectedBase=star_shape
- style=cartoon
- colorMode=monochrome

**hardConstraints：**

no separate floating parts, avoid ultra-thin ears and arms, adequate contact area, stable base, all dimensions checked by downstream geometry engine; any unsupported request is clarified before paid call

生成前预检：已选材料规格、目标高度、至少一个主体、可支撑连接；若要求“悬空漂浮星星”则先要求改成实体连接。

## C.2 创意型 Lux3D 文生 3D 提示词模板（由后台编译）

```text
[SUBJECT] as a single collectible [STYLE] 3D figurine, approximately [HEIGHT_MM] mm tall, intended for [MATERIAL_PROFILE] 3D printing.

Use a stable integrated base. Attach all important features with wide, sturdy connections. Avoid isolated floating pieces, fragile wires, extremely thin accessories, deep inaccessible gaps and tiny overhanging details.

Preserve these user-approved visual details: [APPROVED_DETAILS]. Prioritize a clear readable silhouette and compact geometry. Single isolated object; no scenery or unrelated characters.

This prompt expresses design preferences only. Wall thickness, mesh watertightness, sizing and manufacturability must be independently verified after generation.
```

## C.3 参考图输入：接口约束

若使用纯 img-to-3d，当前公开文档未列出 prompt 字段；结构约束应尽可能体现于经过处理的参考图片，并在生成后独立验收。

若需要结构提示词与图片共同作用，使用 text-to-3d 的 prompt + img（在所用地区和版本实测后启用）。

不要根据平台内部字段名猜测供应商 API 功能。

## C.4 精确 CAD：优先本地参数模板

例如“55×25×4 mm 铭牌，带 4 mm 圆孔”，先确定长度、宽度、厚度、孔径与边距，调用本地 CadQuery/build123d 模板生成 STEP/STL，再用实体几何和最小边距规则实测；该场景无需向第三方模型生成 API 提交任务。

## C.5 成本预算执行规则（伪逻辑）

```text
1) parse_and_validate_request() → DesignSpec
   不合法/不适合制造 → 直接要求修改
   external_cost = 0

2) choose_route()
   → template_CAD
   → constrained_lux3d
   → cannot_support

3) quote_estimated_cost(route)
   若 cost_unknown 或 cost_estimate > remaining_budget
   → 禁止提交付费 API

4) reserve_budget_atomically(task_id, planned_calls)
   submit_external_request_once_with_tracking()

5) poll_existing_task_id()
   timeout 时先核实已建立任务和供应商实际扣费

6) validate_mesh()
   repair_locally()
   若仍不合格且 remaining_budget 不足
   → 终止并恢复用户权益

7) finalize_verified_deliverable()
   debit_one_quota_or_settle_payment()
   log_actual_costs()
```

## C.6 发布前必须通过的成本门槛

- 不得在供应商单次收费未知的情况下向公众开放“每日三次完整 3D 生成”；优先向 Aholo 索取计费规则并通过实际账户验证。
- 每类模型至少测试 20 个不同需求，记录生成调用数、一次成功率、有效壁厚/尺寸、嘉立创通过率、人民币全成本及用户可接受度。
- 日报必须能回答：今天免费产生多少成本、每次付费真实毛利、失败和重试烧掉多少钱、哪个提示词模板导致亏损、哪些商品类别应立即下线。
